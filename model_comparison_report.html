2. C Parser (c.py) Optimization

Enhancing static code syntax analysis to directly maximize Context Quality fed to LLM translation agents:

1. Type-Awareness Extraction Upgrade

  • Current State: The existing parser isolates function signatures and call-graphs purely as raw string tokens. It fundamentally lacks awareness of pointer-indirection complexities (uint8_t* vs cbor_item_t**) or nested allocations inside unions.
  • Solution: Integrate an explicit Type Resolver layer via native Tree-sitter AST queries Targeting parameter_declaration and type_descriptor structures.
  • Impact: Empowers LLM agents to map immutable raw structs cleanly into Java Records while translating nested structures into fully-encapsulated State Classes, minimizing semantic type inference hallucination.

2. Macro & Preprocessor Conditional Expansion

  • Current State: Legacy C codebases heavily employ #define and #ifdef macro headers for targeted cross-platform builds. The naive static parser aggregates unactivated blocks (dead code paths) into context vectors indiscriminately.
  • Solution: Embed a lightweight preprocessor-emulation middleware allowing the parser to flag active compilation variables (e.g., CBOR_PRETTY_PRINTER) to prune or strongly isolate conditional source trees.

3. Native Tree-sitter Lisp Queries Execution

  • Solution: Phase out sequential, multi-pass Python-based recursive abstract syntax tree traversals. Adopt Tree-sitter native query engines leveraging declarative Lisp-like structural pattern matching rules executed in the underlying C layer.
  • Impact: Massive performance speedups across large-scale codebases, completely wiping out pipeline execution latency bottlenecks and I/O choking.
